Environment Overview

Splunk Enterprise was used to query Windows Security Event telemetry with focus on authentication, privilege, credential usage, process creation, and event-volume trend analysis.

  • Primary source: WinEventLog:Security
  • Supporting source validation: System/Application/Setup sourcetypes
  • Analysis method: targeted SPL searches plus aggregate views

  2. Run event-focused SPL hunts across authentication and process events.
  3. Pivot and correlate findings across related Event IDs.
  4. Document positive and no-result outcomes for transparent reporting.
  5. Route artifacts through redaction workflow before publication.

Case Study: Historical Failed Logons and NTLM Investigation

A historical search of WinEventLog:Security identified 41 Windows Security Event ID 4625 records dated July 1 through October 9, 2026. An earlier 24-hour search returned zero matches; widening the time range revealed historical activity. A prior field-based aggregation also required validation against Splunk's actual extracted field names.

The 41 records were grouped by logon type, Windows status and substatus. The breakdown included 16 network logon failures reporting disabled-account status, nine network incorrect-password failures, eight interactive failures requiring further classification, six interactive incorrect-password failures, and two network failures involving unknown-account status.

Focused Analysis: July 28, 2026

Nine incorrect-password network logons were associated with two distinct populated source addresses. One source contributed five events and the second contributed four. All nine records reported NtLmSsp as the logon process and NTLM as the authentication package. The source groups showed two and three distinct account field values, respectively; field-value counts do not independently establish the number of valid user accounts.

Analyst assessment: Repeated NTLM authentication failures warrant contextual triage. The observed records do not establish password spraying, brute-force activity, unauthorized access, or compromise. Root cause remains undetermined. Counts and conclusions reflect the historical Splunk search scope, not a claim of continuous monitoring or a deployed alerting rule.

Findings or Outcomes

  • Authentication and logoff telemetry supports account activity monitoring workflows.
  • Privileged and explicit credential events provide high-value investigation pivot points.
  • Process creation visibility enables baseline behavior review and suspicious execution triage.
  • A 24-hour no-result authentication search was reconciled with 41 historical Event ID 4625 records by correcting search scope.

Lessons Learned

A zero-result search is scoped to its selected time range and filters, not proof of an absence of historical activity. The 4625 review exposed the importance of time-range selection, field extraction validation, and separating authentication anomalies from confirmed incidents.
