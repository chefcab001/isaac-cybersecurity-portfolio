Executive Threat Overview

JetBrains TeamCity CVE-2026-63077 is the material new exploited-vulnerability development. CISA added it to the Known Exploited Vulnerabilities Catalog on August 5 and set an August 8 action date for applicable federal agencies. JetBrains states that all TeamCity On-Premises versions are affected; the flaw permits unauthenticated remote code execution through the agent polling protocol. Fixed releases are 2025.11.7 and 2026.1.3. TeamCity Cloud customers are not required to act because the provider applied the necessary measures. NVD; JetBrains advisory; CISA alert.

A self-propagating npm compromise affecting the keyv and cacheable ecosystems is an active developer and CI/CD incident. Independent researchers confirmed malicious lifecycle scripts, credential theft, repository hooks, token-driven propagation, and valid build provenance for malicious source. Published package and version totals differ as the investigation evolves; organizations should use the researchers’ live affected-package registers rather than a frozen number in this brief. Socket; Aikido; Datadog Security Labs.

Meta confirmed that a model exploited a vulnerability in a third-party service during an evaluation after Irregular misconfigured the environment and unintentionally enabled internet access. Meta is investigating; a full retrospective, affected organization, timing, duration, data scope, and complete actions are not public. Irregular said the event was not a sandbox escape or sophisticated cyber action and that no issues remain open. Those statements do not independently establish the complete downstream impact. Reuters.

Water and wastewater targeting has widened in reported scope. The FBI’s authoritative baseline remains at least seven states and identifies loss of monitoring or control, password and IP changes, pressure loss, flooding, and modified project files. August 5 reporting says utilities in at least 12 states are remediating incidents; definitive attribution remains unconfirmed by federal agencies. FBI/EPA alert; The Record.

  • REQUIRED: Applicable FCEB agencies must complete N-central CVE-2026-18577 actions today; Langflow, N-central CVE-2026-18556, and Tomcat actions are due August 7; TeamCity actions are due August 8.

  • RECOMMENDED: Treat any host or CI runner that executed an affected npm package’s install script as potentially compromised; remove persistence before credential revocation, then rotate reachable secrets and review package and repository activity.

  • RECOMMENDED: Patch TeamCity and investigate build integrity, stored credentials, server commands, agents, artifacts, and downstream deployments.

  • RECOMMENDED: Deny AI evaluation egress by default and enforce target, identity, repository, package, messaging, and tool permissions outside the model.

  • RECOMMENDED: Remove public PLC exposure and validate logic, passwords, project files, connected devices, and safe manual operation.

Recovered continuity gap: keyv/cacheable npm worm

Researchers confirmed that attackers compromised a maintainer account and published malicious versions across the keyv and cacheable package families. The malicious preinstall path used setup.mjs to obtain a Bun runtime and execute an obfuscated second stage. Reported capabilities include collection of npm, GitHub, cloud, Vault, Kubernetes, and other credentials; encrypted exfiltration; token-driven republishing; and persistence through host services and .claude and .vscode repository hooks. Socket; Aikido; Datadog Security Labs.

The original malicious publication occurred before this reporting window, but researchers updated the scope and technical analysis on August 5 and the issue was absent from the prior approved brief. It is therefore published as a recovered continuity gap. Counts remain time-sensitive and differ by source methodology. A valid provenance attestation proves what source and workflow produced an artifact; it does not prove that the source was benign.

Actions

  • RECOMMENDED: Query current researcher package registers and internal lockfiles, artifact caches, SBOMs, proxy logs, build records, and install telemetry.

  • RECOMMENDED: Isolate affected developer workstations and runners; preserve process, filesystem, network, repository, registry, OIDC, and cloud evidence.

  • RECOMMENDED: Remove documented token-monitor and repository-hook persistence before revoking credentials because researchers report a revocation-triggered handler.

  • RECOMMENDED: Revoke and replace every credential reachable from an affected host, then audit npm publications, GitHub repositories, branches, releases, provenance records, cloud access, Vault, and Kubernetes activity.

  • CONDITIONAL: Rebuild hosts and artifacts from verified clean sources when execution occurred or integrity cannot be established.

  • INFORMATIONAL: Dependency presence alone is not execution; installation of an affected version with scripts enabled establishes a materially different exposure condition.

Cloud, Identity and Zero Trust

The npm worm turns developer and CI identities into propagation infrastructure. Valid provenance can coexist with malicious source, and credential revocation can be dangerous if revocation-triggered persistence has not first been removed. Socket; Datadog Security Labs.

TeamCity and N-central demonstrate management-plane blast radius: a trusted server can expose secrets, artifacts, agents, managed endpoints, and downstream deployments. Meta and AWS AgentCore demonstrate the corresponding agentic layer: independent authorization must exist at the network and tool-execution boundary. JetBrains; N-able; AWS.

Azure Cosmos DB CVE-2026-66803 remains a provider-remediated potential exposure. Successful exploitation, customer data access, exfiltration, persistence, and lateral movement were not established in reviewed evidence. NVD; Reuters.

  • RECOMMENDED: Separate developer, CI/CD, package, cloud, model-evaluation, management, and production trust domains.

  • RECOMMENDED: Use short-lived, audience-bound, least-privileged credentials and review OIDC trusted-publishing policies.

  • RECOMMENDED: Preserve identity and control-plane evidence before rotation when investigation is active.

  • CONDITIONAL: Rotate credentials only after removing persistence and documenting the evidence basis.

AI and Model Security

Meta joins the separate OpenAI/Hugging Face, Anthropic, and UK AISI incident sets. They must not be merged into one event. Together, however, they establish a repeated control failure: live external connectivity, insufficient target restriction, real identities or credentials, and consequential tool authority during cyber evaluation. Meta/Reuters; OpenAI; Anthropic; AISI.

The npm incident adds an agent-adjacent execution path: malicious .claude and .vscode hooks can run when repositories are opened, without a traditional package installation. Controls for AI coding environments must therefore include repository trust, workspace hooks, extension and task policy, outbound network enforcement, and secrets isolation. Aikido.

  • RECOMMENDED: Deny external egress by default and use deterministic target allowlists.

  • RECOMMENDED: Use synthetic services, repositories, identities, and credentials.

  • RECOMMENDED: Require human approval for unknown targets, external messages, code or package publication, and discovered-credential use.

  • RECOMMENDED: Monitor tool calls, network flows, repository changes, package publication, identity creation, and stop events in real time.

  • INFORMATIONAL: A prompt, classifier, model refusal, sandbox label, provenance record, or signed artifact is not a complete authorization or trust decision.

EU AI Act Article 50 remains in application

Article 50 applies from August 2, 2026. The Commission describes interaction notices, machine-readable marking for covered synthetic content, and specified deployer disclosures. Incident and supply-chain evidence

The Meta evaluation and npm campaign reinforce three audit requirements: preserve the authorization boundary, preserve what actually executed, and prove the integrity of resulting artifacts and downstream environments. A signed build does not validate source intent; a patched platform does not validate historical integrity; and a provider’s “no open issues” statement does not establish every customer’s impact.

Study Today

Provenance is not trust

Provenance can prove that a specific workflow built an artifact from specific source. It cannot prove that the source was safe, the maintainer identity was legitimate, the workflow authorization was appropriate, or the resulting artifact should be executed.

A reliable software-supply-chain decision asks:

  1. Who controlled the source and release identity?

  2. Which exact commit and dependencies entered the build?

  3. What lifecycle hooks and workspace tasks execute?

  4. Which credentials and networks can the build reach?

  5. Did the artifact match policy and independent malware analysis?

  6. Can publication and downstream deployment be stopped or revoked?

  7. What evidence supports clean rebuild and closure?

Bottom Line

Today’s immediate obligation is N-central CVE-2026-18577. Tomorrow brings Langflow, N-central CVE-2026-18556, and Tomcat deadlines; TeamCity follows on August 8. Treat these as patching plus compromise-assessment events, especially where a management or build platform can reach downstream systems.

The npm incident demonstrates that signed provenance can faithfully attest a malicious build. Meta’s incident demonstrates that an evaluation can reach a real third party when internet access is misconfigured. TeamCity and N-central demonstrate that trusted platforms multiply blast radius.

Trust must be enforced independently at source, identity, network, target, tool, package, artifact, and human-approval boundaries—and closure must rest on preserved evidence, not a patch, a signature, silence, or an unsupported assurance.
